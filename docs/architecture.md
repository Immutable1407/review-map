# Architecture and data contracts / 架构与数据接口

## Components

| Stage | Implementation | Output |
| --- | --- | --- |
| Acquisition | External `yichen-content-archive`; independent `scripts/acquire.py` bridge | Local run, executor log, metadata/media, `capture.json` |
| Place extraction | Your agent using `prompts/extract-places.md`, or a human | Intake JSON with source text and exact evidence |
| Registration and staging | `scripts/ingest.py` | Immutable Raw versions, ledgers, pending review and place lines |
| Matching | `scripts/build_places.py` | Generated places and ambiguous/missing candidate queues |
| Human calibration | `web/review.html`, `scripts/apply_review_results.py` | Selected branches, geocoded addresses, corrected tags |
| Presentation and reviews | `web/assets/atlas.*`, `scripts/serve.py` | MapLibre map, navigation, SQLite ratings/comments |

Acquisition mechanics come from the upstream skill, not from the bridge. Review Map's integration begins with bounded executor invocation and continues through evidence management, places and the review application. [ATTRIBUTION.md](../ATTRIBUTION.md) records the exact component links and inspected interface revision.

## Intake

`examples/intake.json` is a complete synthetic example; `examples/intake.schema.json` describes its shape.

A source carries `source_id`, `platform`, `canonical_url`, `title`, `capture_status`, `content_state`, `text_source` and `text`. Prefer platform IDs such as `douyin:<id>`. Keep the same identity across retrievals; do not put an access token into an identity.

| Field | Values |
| --- | --- |
| `capture_status` | `success`, `partial`, `failed`, `unsupported`, `needs_auth` |
| `content_state` | `complete`, `partial`, `metadata_only`, `media_complete_text_partial`, `stub` |
| `text_source` | `platform_original`, `platform_auto`, `platform_description`, `user_provided`, `jina_reader`, `local_ocr`, `authorized_asr`, `none` |

Each place has a name, optional known city, category, recommended-food list, source IDs, `confirmation` and evidence quotes. A quote must occur in a referenced source's supplied text. A failed/stub source or unverified quote does not become a place batch. Confirmation of a name does not establish a street address.

The stored category vocabulary is `美食` (food), `甜品` (dessert), `咖啡` (coffee), `酒吧` (bar), `公园` (park), `展馆` (gallery), `小店` (shop), `游玩` (outing). The calibration desk can attach more than one tag; `category` is the first tag.

## Local acquisition state

```text
data/acquisition/
  runs/<run-id>/             upstream executor outputs + bridge capture.json
  raw/<source-hash>/<n>.json immutable registered source versions
  compiled/<run-id>/         review.json, places.md, metadata.json, handoff.json
  ingest-ledger.jsonl        one identity registration per source
  retrieval-ledger.jsonl     content hash and Raw path per retrieval version
  handoff-ledger.jsonl       delivered item keys and destination batches
```

Re-ingesting unchanged content adds neither a Raw version nor an identity row. A changed capture creates a new Raw version. Every compilation gets a separate run; old source files and ledgers are not rewritten.

`--deliver` writes only confirmed, evidence-backed names to a new `raw/YYYY-M-D_update.md` and annotates each item in `config/raw-update-metadata.local.json`. Filename collisions use `-2`, `-3`, etc. A repeated delivered item does not create another handoff. Same-name places in different cities remain in acquisition review until their names/branches are disambiguated.

Unknown names stay upstream. A confirmed name without a known city can be staged with an empty city and will enter downstream manual calibration, not an unconstrained nationwide search. Both source IDs and canonical source URLs follow the item into generated places. URL query parameters are omitted from generated provenance links.

## Matching and calibration

Name similarity and AMap POI type determine candidate rankings. Low scores, short-name mismatches and close same-brand branches remain unresolved. Identity uses AMap POI ID where available; distinct IDs at the same mall are not merged by coordinates alone. Aliases, recommendations and provenance are merged when IDs match.

The desktop workbench has three parts:

1. Multi-select candidate branches; “all wrong” is exclusive.
2. Manual addresses for missing/rejected candidates.
3. Multi-select tag correction for existing places.

Exports may be partial. Unmentioned rows remain pending. All-wrong rows stay in manual entry, and failed address geocoding is retriable. Stable IDs and incremental seed merging preserve progress across rebuilds and repeated imports.

## Map and review service

The frontend consumes `window.PLACES_DATA` generated by the Python pipeline. MapLibre/OpenFreeMap uses WGS84 display coordinates; gcoord transforms a copy of the AMap GCJ-02 `location`. AMap navigation retains the original coordinates. Nearby distances are straight-line estimates.

`GET /api/session` and `GET /api/reviews` support public reading. Authenticated `PUT`/`DELETE /api/reviews/<place-id>` save one personal review per place. `POST /api/session` signs in; `POST /api/logout` revokes the session; `GET /api/export` requires login.

Passwords use salted scrypt hashes; session identifiers are hashed in SQLite and sent in HttpOnly/SameSite cookies. Review revisions reject stale writes. Builds do not modify the database. The calibration page is available locally; remote access requires login. The API does not apply calibration exports—those are imported by the local CLI.

## 中文摘要

采集层明确使用 yichen-skills 的执行器；地点提炼由 Agent 或人工基于实际正文、字幕、OCR 证据完成。入库层分开保存来源身份、获取结果和内容完整度，不用“下载成功”代替“已取得全文”。来源版本不可变，台账追加写入；确认后的地点单独交接给高德匹配和校对台。

未选条目继续待处理，不确定名称不自动上图；已确认名称但未知城市进入地址补充。高德 POI ID 决定主要去重身份，别名、推荐菜和来源一并保留。地图构建与 SQLite 评价分离，登录后才可写入，重建地图不会覆盖点评。
